# Обязательные правила работы агентов

Правила действуют для всего репозитория. Перед работой учитывать также `CLAUDE.md`
и порядок ведения задач в `BACKLOG.md`.

## Узкая область изменений

- Каждое изменение кода должно решать конкретную узкую задачу с проверяемым
  результатом. До изменения определить цель, границы и критерии готовности.
- Менять только то, что необходимо для этой задачи. Сопутствующий рефакторинг,
  форматирование постороннего кода, обновление зависимостей и другие улучшения
  не включать без необходимости для выбранной задачи.
- Если работа требует самостоятельного подготовительного изменения, оформить
  его отдельной задачей в бэклоге, связав с исходной. Не расширять исходную
  задачу незаметно и не обходить блокировку временными заглушками.

## Блокирующие задачи

- Если задачу нельзя завершить из-за блокировки, обязательно отразить это
  в `BACKLOG.md`. Если исходной задачи там нет, сначала добавить её.
- У исходной задачи указать состояние «Заблокирована», конкретную причину,
  подтверждающее наблюдение, ID блокирующих задач и условие снятия блокировки.
  Не отмечать задачу завершённой, пока её критерии не выполнены.
- Для каждой необходимой блокирующей работы сначала проверить существующий
  бэклог. Если подходящая задача есть, сослаться на её ID; если нет — создать
  отдельную задачу с новым ID, проблемой, результатом и критериями готовности.
  В ней указать, какую исходную задачу она блокирует. Не создавать дубликаты.
- Если препятствие внешнее (например, нет доступа или решения владельца),
  записать необходимое действие и того, от кого оно требуется; отдельная
  блокирующая задача всё равно должна быть связана с исходной.
- Остановить зависимую часть работы и сообщить владельцу о блокировке.
  Наличие новой блокирующей задачи не даёт автоматического разрешения её выполнять.
- После устранения причины проверить условие снятия блокировки, обновить состояние
  и только затем продолжать зависимую работу в рамках разрешённой задачи.

Эти правила не меняют разрешения на коммиты, пуши и выпуск в production.
