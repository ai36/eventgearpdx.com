# Правила работы с проектом

## Область действия плагина claude-code-setup

- Плагин `claude-code-setup` и его скилл `claude-automation-recommender` анализируют
  **только код проекта**: `src/`, конфигурацию сборки и линтеров, `package.json`.
- Вне области: `public/blog/` (контент), `docs/`, `CHANGELOG.md`, `BACKLOG.md`,
  `_agents/` (SEO-генератор и его настройки). Не читать их для рекомендаций,
  не предлагать автоматизации по ним.
- Плагин read-only: он ничего не меняет, только советует. Любую его рекомендацию
  внедрять отдельно и по прямой просьбе владельца.

## Переработка контента

- Переработка блога по профилям клиентов завершена 23.09.2026. Порядок выполнения
  пункта и итоговая раскладка сохранены в `docs/content-restructure-plan.md` —
  оттуда брать процесс, если переработка понадобится снова.
- Правила для самих статей (кто клиент, что можно обещать, формат FAQ) живут в
  `_agents/domain-expertise.md` и применяются к любой правке контента, не только
  к тому, что пишет агент.

## Git

- Вся работа ведётся в ветке `dev`: коммиты и пуши только в `dev`.
- В `main` ничего не коммитить и не пушить. Pull request'ы в `main` не создавать.
  Слияние `dev` → `main` владелец делает сам, вручную, через интерфейс GitHub.
- После завершения задачи не спрашивать про PR или merge в `main`.
- Коммитить и пушить в `dev` только по просьбе владельца.
- Все действия с репозиторием выполняются от имени владельца. Не указывать Claude
  как автора или соавтора: никаких строк `Co-Authored-By: Claude…`, «Generated with
  Claude Code» и подобной атрибуции в коммитах, pull request'ах, issue и комментариях.
- Владелец иногда правит код вручную. Незнакомые изменения в рабочей копии не трогать
  и не откатывать — спросить, что с ними делать.
